## 6. Data safety form (App content → Data safety)

Hatiwal collects the following. Declare each as collected, tied to identity, and state why.

| Data type | Collected? | Shared? | Purpose | Notes |
|---|---|---|---|---|
| Name | Yes | No | Account management, App functionality | Shown on profile/listings |
| Email address | Yes | No | Account management | Login (devise_token_auth) |
| Phone number | Only if collected at signup | No | Account management | Declare only if used |
| Photos | Yes | No | App functionality | Listing images the user uploads |
| Messages (in-app) | Yes | No | App functionality | Buyer↔seller chat |
| Approximate location | Yes | No | App functionality | Listing location / nearby |
| Precise location | Yes (uses FINE_LOCATION) | No | App functionality | Setting a listing's location on map |
| App activity (saved listings) | Yes | No | App functionality, Personalization | Favourites |

Answers to the standard questions:
- **Is data encrypted in transit?** → **Yes** (HTTPS / WSS).
- **Can users request deletion?** → Provide a way (account deletion endpoint or email).
  If none exists yet, add one — Google requires a deletion path.
- **Is any data sold?** → **No.**
- **Is data collected required or optional?** → mostly required for functionality.

⚠️ Location: you request `ACCESS_FINE_LOCATION` in `app.json`, so you must declare
**precise location**. If you actually only need approximate, consider dropping FINE
permission to simplify this declaration.

## 8. Order of operations (to actually publish)

1. Upload the production `.aab` (from `eas build`) to **Internal testing** → install on your

2. Complete **all** of section 5 (App content) — publishing is blocked until every item is green.
3. Fill the **Store listing** (sections 1–4) in all 3 languages.
4. Create a **Closed testing** track → add **12+ testers** → publish a release → the
   14-day clock starts. (New personal accounts must run closed testing ≥14 days.)
5. After 14 days with 12+ opted-in testers → **Apply for production**.
